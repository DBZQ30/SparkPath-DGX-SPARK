## 1. 背景与目标

2023 版培养方案在**常规型**之外增设**科学研究型 / 交叉融合型 / 创新创业型**三条路径，四种路径的**学分替代规则、申请节点、毕业设计要求各不相同**。同时，管理学院本科生在**大一第二学期要"专业选择/分流"**（未定主修 → 选专业）、后续还可能**转专业 / 辅修**，但学生普遍不知道"要补多少学分、压力会不会爆、什么时候该做什么"。

现有两个 skill 只解决"**读懂方案**"（`training-plan-interpretation`）与"**发现问题**"（`academic-warning`），**不解决"我该怎么走"**。本功能面向**新生 / 低年级本科生**，把"路径选择 → 四年路线图 → 专业选择/转专业/辅修模拟 → 压力评估"做成**可参考、可重跑**的方案，**不替学生拍板**。

四个核心能力：

| # | 能力 | 输出 |
|---|------|------|
| 1 | **四方向四年路线图** | 选定方向后，逐学期给出"该修哪些课 + 竞赛/科研/证书节奏 + 培养模式申请节点 + 学分合计" |
| 2 | **专业选择（分流）模拟** | 大一未定专业：接收计划 + 志愿策略（3 个顺序志愿）+ 综合成绩构成 + 各志愿对应的四年路线图 |
| 3 | **转专业 / 辅修模拟** | 新增修读要求、**可抵扣/需补修学分**、学业压力变化、时间与政策约束（含 ACCA 降级、3 学年末补修红线） |
| 4 | **可重跑更新** | 目标变了、转专业了，**重新跑一遍同一条命令即更新**，不残留旧结论 |

### 1.1 使用场景

- **主要入口**：学生在小程序聊天框提问——
  - "我想走科学研究型，四年怎么安排"；
  - "我大一还没定专业，三个志愿怎么填"；
  - "我想转大数据，要补多少学分、能不能赶上推免"；
  - "辅修会计压力大不大"。
- **结果呈现**：聊天框给**摘要 + `actions` 卡片**；完整路线图/对比/模拟在**小程序「学业规划」页**查看（见 §12）。
- **重跑**：学生改方向/改目标专业后，skill 用新参数重新调用，输出即更新。

### 1.2 交付边界（本期）

| 做 | 不做 |
|----|------|
| 4 个本科专业 × 2023 级（年级维度预留）× 四种路径的四年路线图 | 全校所有专业（按同一机制扩展） |
| **专业选择（分流）模拟**（大一未定专业，3 顺序志愿，接收计划 + 综合成绩构成） | 替学生决定志愿顺序（只给策略与权衡） |
| **转专业模拟**（官方接收计划 + 已修抵扣/需补修 + 压力 + 政策红线） | 转专业的**录取保证**（考核成绩/面试/综测不可预测，只做测算与提示） |
| 个人化抵扣/压力（读 `warning.db` 成绩，**本人只读**） | 选课代选、成绩/绩点/排名查询、学业预警判定（各归其 skill） |
| 辅修模拟（**待教务提供辅修教学计划后接入**，本期预留模型与入口，见 §6.5） | 辅修报名与资格认定 |
| 建议节奏（竞赛/科研/证书，**明确标注"建议、非官方"**） | 替学生决定方向/转专业/辅修（只给可参考方案与权衡） |

## 2. 已确认决策（2026-09-23/24）

| 项 | 决策 |
|----|------|
| **方向集合** | 四种：常规型 / 科学研究型 / 交叉融合型 / 创新创业型（与培养方案、PPT 一致；"优本计划"作为科学研究型的进阶子项，不单列方向，见 §4.5） |
| **场景集合** | ① 方向路线图；② **专业选择/分流**（大一未定专业）；③ **转专业**；④ 辅修（待文件）。四者可独立触发，也可串联（分流选定专业 → 再排路线图） |
| **辅修 / 转专业数据** | **转专业政策已到位**（2026 细则 + 考核安排，2026-09-24 入库设计）；**专业选择方案已到位**（2025 级方案 + 志愿填报流程）；**辅修教学计划仍待提供**（本期预留） |
| **个人数据** | **读取 `warning.db` 成绩**（本人只读）用于个人化抵扣与压力计算。**这是对 009 "两功能数据隔离"的一处有意例外**，仅在本人查询场景下、按学号只读，见 §13 |
| **结果呈现** | 聊天摘要 + **小程序「学业规划」页** + `actions` 一键跳转 |
| **竞赛/科研/证书节点** | **官方硬节点**（培养方案/三类模式细则/替代指导意见/转专业细则里写死的）**+ 通用建议模板**（明确标注"建议、非官方硬性规定"） |
| **压力量化** | 以官方"**每学期修读原则上 ≤25 学分；前一学期学分绩 >90 可适当超出 2 学分**"为基准，定义负荷率与四档压力（见 §7）；转专业额外叠加**补修负荷**与**降级**因素 |
| **命名与技术形态** | 目录 `shared_skills/multi-path-academic-planning/`；**复用并扩展 `trainingplan` 包与 `data/training_plan.db`**（新增子命令与 `plan_*` 新表），与解读 skill 同库 |

**关键事实（已核查）**：

1. 培养方案 docx **自带**四种路径规则与清单（"①科学研究型-本学科研究生进阶课程清单""②交叉融合型-跨选课程专业范围要求""③创新创业型培养模式"），**但当前 `trainingplan` 解析器未抽取**：`plan_course.note` 全空、无培养模式表。需新增解析（§3.2）。
2. 各专业替代学分数不同：**工商 6 / 工业工程 6 / 会计（ACCA）6 / 大数据 8**（大数据研究生进阶课程仅 4 门 × 2 学分 = 8，恰好覆盖）。
3. 培养方案写明：**每学期修读原则上 ≤25 学分**；培养模式申请在**大三第二学期**（书面申请 → 学院审批 → 参加对应类型毕业设计）。
4. `warning.db` 已有成熟的**方案匹配与已修分类**能力（`academicwarning/rules.py::Prep`：`_match_plan_course` / `gained_credits_by_category` / `missing_courses` / `unmatched_credits`），**可直接复用于"可抵扣学分/缺口"计算**（§6）。
5. **转专业官方抵扣口径已明确**（2026 细则 五-2）：**已修课程学分 ≥ 目标专业"应修课程表"中同一课程 → 免补修；未修或学分不足 → 必须补修**；**第三学年结束前修完，否则不得参加当年免试研究生推荐**；**转入 ACCA 须降级就读**。
6. **专业选择（分流）** 是独立场景：大一第二学期、**3 个顺序志愿**、"专业志愿优先、遵从综合成绩"、综合成绩 = 70% 学业 + 20% 专项考查 + 10% 综测。

## 4. 四种路径规则模型

### 4.1 规则总表（来源：四专业培养方案 + 三类培养模式实施细则）

| 维度 | 常规型 | 科学研究型 | 交叉融合型 | 创新创业型 |
|------|--------|------------|------------|------------|
| 定位 | 满足方案修读要求，达到毕业条件 | 深入专业知识，强化科研训练 | 突出学科交叉、产教融合 | 培养创新思维，增强创新创业能力 |
| 核心替代规则 | 无 | 在专业核心课/选修课模块，修读**本学科研究生进阶课程** ≥ **6/8 学分**（按专业）替代专业选修课 | 在专业核心课/选修课模块，修读**某确定跨选专业的交叉课程** ≥ **6/8 学分** 替代专业选修课 | 除毕业设计和军训外，**创新创业成果**替换集中实践 ≥ **6 学分** |
| 范围约束 | — | 本专业公布的研究生进阶课程清单 | **只交叉融合一个专业**的课程（PPT 明确）；范围由本专业公布 | 成果类别：大创项目 / 大学生竞赛（榜单内）/ 创办企业及运营 |
| 可替代环节 | — | 专业选修课 | 专业选修课 | 基本技能训练、专业实习、课程（项目）设计、科研训练、专业综合性实验（践） |
| 申请节点 | — | **大三第二学期**书面申请 → 学院审批 → 科学研究型毕业设计 | 同左 → 交叉融合型毕业设计 | 同左 → 创新创业型毕业设计 |
| 审批不通过兜底 | — | 按常规型毕设；**已修研究生课程仍按专业课认定** | 按常规型毕设；**已修跨选课程仍按专业课认定** | 按常规型毕设；**已替换成果仍按集中实践认定** |
| 适合人群（建议，非官方） | 稳妥、按部就班 | 计划读研/直博、想早进课题组 | 想拓宽学科面、复合背景 | 想创业/竞赛、实践成果多 |

| 会计学（ACCA） | 6 | 6 | 大数据管理与应用 / 经济学 / 金融学 / 法学 / 哲学 / 社会学 |

### 4.3 研究生进阶课程清单（示例，工商管理）

`管理研究方法论 I/II、高级管理研究、创业管理研究前沿、战略管理专题研讨、国际商务研究前沿`（各 2 学分；其余专业清单见 §3.2 解析结果）。

### 4.4 创新创业型替代规则（附件5，示例口径）

- **成果类别 → 替代内容**：大创项目、大学生竞赛（中国高教学会榜单，附件含 53 项）、创办企业及运营。
- **分级别给分**：立项级别、结题验收、完成人身份、获奖级别等要素影响替代成绩（`plan_mode_rule` 存要素表）。
- **下限**：可替换集中实践 ≥ 6 学分，**不含军训、毕业设计**。

### 4.5 "优本计划"的归属（重要边界）

PPT 中的**优本计划（本研贯通）**是另一套机制（修读 ≥2 门研究生课程、进导师课题组、两助一辅、可缩短研究生学习时间 0.5~1 年等），**不属于四种培养路径**。本设计**不单列为方向**，而是作为**科学研究型的进阶子项**在路线图中提示（"若同时入选优本计划，可提前…"），并标注其申请条件以学院通知为准。

## 5. 四年路线图生成

### 5.1 输入 / 输出

- **输入**：专业、入学年级、方向（四选一）、（可选）学号。
- **输出**：逐学期卡片（1-1 … 4-2），每张含：课程清单（必修 + 按方向调整后的选修/替代）+ 学分合计 + 负荷档 + 该方向动作节点；末尾给培养模式申请节点与毕业条件自查清单。

### 5.2 算法步骤

1. **取基准**：`plan_semester_course`（分学期推荐课表）+ `plan_course`（课程总表，含类别/学分/学期/备注）→ 常规型四年基线。
2. **按方向调整**：
   - **常规型**：基线不变。
   - **科学研究型**：在 3-1 / 3-2 / 4-1 的专业选修学分内，用 `plan_mode_course`（研究生进阶）替换等学分课程；插入"联系导师 / 进课题组"建议节点（大一下~大二上）与"大三第二学期申请"硬节点。
   - **交叉融合型**：在专业选修学分内，用"跨选专业课程清单"替换 ≥6/8 学分；插入"大二确定跨选专业 + 跨选课程修读"建议节点与申请硬节点。
   - **创新创业型**：集中实践环节中除军训/毕设外的 ≥6 学分改由"创新创业成果"替代；插入"大创申报（大二）/ 竞赛 / 成果沉淀（大三）/ 结题认定"建议节点与申请硬节点。
3. **约束校验**：
   - **先修**：`plan_prereq_edge`（仅 `verified=1`）保证 `to` 学期 ≥ `from` 学期；未校对的边不参与硬约束，仅作提示。
   - **学分上限**：每学期合计 ≤ 25（>25 需提示"上学期绩点>90 可+2，否则超限"）。
   - **总量**：四年合计 ≥ 毕业总学分 + 课外实践 8；各模块（通识/大类/专业/集中实践）达标。
4. **生成节奏节点**：官方硬节点（库内）+ 通用建议模板（`references/path-rhythm.md`，标注"建议、非官方"）。
5. **压力量化**：按 §7 计算每学期负荷档与相对基线的 Δ。

## 6. 专业选择 / 转专业 / 辅修模拟

> 三者**共用一套"目标方案 vs 已修课程"的抵扣/缺口引擎**（复用 `academicwarning.rules.Prep`），差异在**目标来源、政策约束、压力模型**。

### 6.1 通用输出

- **新增修读要求**：目标方案要求中尚未满足的部分（按模块）。
- **可抵扣 / 需补修**：已修课程中能对应到目标方案的课程与学分（**以实际修读为准**）。
- **学业压力变化**：剩余学期需补学分 → 每学期负荷 vs 基线（§7），并叠加政策时间红线。
- **可参考方案 + 风险提示**，**不替学生拍板**。

### 6.2 转专业（官方规则已到位）

**官方事实（《管理学院 2026 年本科生转专业实施细则》）**：

1. **接收计划**（按年级 × 学院内/跨学院，示例 2026）：

   | 专业 | 2025 级（大一） | 2024 级（大二） | 2023 级（大三） |
   |------|:---:|:---:|:---:|
   | 大数据管理与应用 | 8 | 2 | 2 |
   | 工业工程 | 8 | 2 | 2 |
   | 工商管理 | 4 | 2 | **0** |
   | 会计学（ACCA） | 10 | 2 | **0** |
   | 合计 | 30 | 8 | 4 |

2. **申请条件**：在籍在校；无违纪违法；符合学校其他规定。
3. **流程**：教务系统（`ehall.xjtu.edu.cn`）填报志愿（**每人仅 1 个专业志愿，提交后不可更改**）→ 提交转专业申请表 + 成绩单 → 学院初审 → 考核 → 教务处公示（3 天，公示期内可书面撤销）→ 学籍异动。
4. **考核**：**笔试（高等数学 I + 英语）+ 综合考查（面试），各占总成绩 50%**；面试考察英语听说、专业认知、**未来学业规划**、综合素质。
5. **录取**：成绩优先（笔试 50% + 综合 50%），按计划录满；报名 < 计划时达标者全收，**暂不达标者可"预修"**（签协议，一年内获指定课程学分，次年办理转入）。
6. **补修（= 抵扣口径）**：
   - 按目标专业培养方案补修；
   - **已修课程学分 ≥ 目标专业"应修课程表"同一课程 → 无需补修**；未修或学分不足 → 必须补修；
   - **必须在第三学年结束前修完补修课程，否则不得参加当年免试研究生推荐（推免红线）**；
   - **大一/大二/大三转入会计学（ACCA）均须降级就读**。

**模拟输出（在通用输出基础上）：**

- **资格与计划匹配**：当前年级 + 目标专业 → 接收计划数、是否"学院内/跨学院"、是否可报（如大三报工商/ACCA 计划为 0 → 明确提示不可报）。
- **可抵扣 / 需补修清单**：已修课程 vs 目标专业"应修课程表"逐门比对（学分 ≥ 即免补修）。
- **压力与红线**：把需补修学分摊到剩余学期 → 每学期负荷；**若"剩余学期 × 25 < 需补修学分"或"第三学年末修不完"→ 标红**，并给出"需降级/需暑期修读/需放弃推免"等权衡提示。
- **考核准备建议**：笔试（高数 I + 英语）备考、面试材料（成绩单、简历、**未来学业规划**陈述）。
- **风险提示**：录取按考核成绩择优、存在竞争；预修需签协议；**录取与否以学院/教务处公示为准**。

### 6.3 专业选择 / 分流（大一未定专业，官方规则已到位）

**官方事实（《管理学院 2025 级本科生专业选择实施方案》）**：

1. **接收计划**（2025 级）：工商管理 33 / 工业工程 33 / 大数据管理与应用 32（合计 98）。
2. **学生范围**：未确定主修专业的 2025 级在籍在校学生（复学/留级已定专业者不参加；港澳台、预科转入、留学生不参加）。
3. **时间线**：大一第二学期启动（5 月公布方案 → 6 月两轮志愿填报 → 6 月专项考查 → 7 月成绩确认/录取/公示 → 变更学籍）。
4. **志愿**：**按顺序选报 3 个专业志愿，不得少报**。
5. **录取规则**：**"专业志愿优先，遵从综合成绩"**——第一志愿 ≤ 计划直接录取；> 计划参加专项考查，按综合成绩排名依次录取；再依次启动第二、第三志愿；未填志愿者在有余量专业中调剂。
6. **综合成绩 = 70% 学业成绩（学院提供）+ 20% 专项考查（面试）+ 10% 综合素质测评（书院提供）**。
7. **学业成绩口径**：培养方案规定必须修读课程的学分成绩；**补考/重修及格按 60 分计；应修未修 / 缓考未补考按 0 分计**。
8. **面试**：15 分钟/人，2 分钟自我介绍（不得报姓名学号）、抽 1 题 + 专家提问；指标：沟通能力、逻辑思维、创新思维、目标计划能力、进取心。

**模拟输出：**

- **接收计划与竞争态势**：各专业计划数；结合学院实时反馈（若有）提示"热度"。
- **志愿策略建议**：按"冲 / 稳 / 保"给出 3 个顺序志愿的**参考组合**（**仅供参考，不替学生决定**）。
- **综合成绩测算**：能算的部分——**学业成绩**（用 `warning.db` 已修必修课程成绩，按官方口径：补考/重修及格计 60、应修未修计 0）；**不能算的部分**——专项考查（面试）与综合素质测评（书院），**明确标注为未知/需自估**。
- **各志愿 → 四年路线图**：对每个志愿专业给出（专业 × 年级 × 四方向）路线图入口，帮助学生"先看四年再填志愿"。
- **操作指引**：教务系统填报步骤（来自《志愿填报操作流程》）。
- **风险提示**：志愿一经提交不可更改；录取以学院公示为准。

### 6.4 转专业"应修课程表"的来源

"应修课程表"= 目标专业培养方案中**转入学生需补修的课程集合**（可由 `plan_course` 中目标专业的必修/核心课程 + 转专业细则中的补修说明推导；若学院单独发布"应修课程表"文件，则优先用该文件）。**本期先用目标专业培养方案课程表近似，并标注口径来源**；待学院提供专门"应修课程表"后替换。

### 6.5 辅修（本期预留）

- 待用户提供辅修教学计划后，走 `training_plan` 上传入口（`program_type=辅修`）解析入库。
- 模拟逻辑与转专业同构（辅修要求 vs 已修 → 抵扣/新增/压力），差异在于**辅修学分不替代主修**，而是**叠加**，压力评估更关键。
- 数据模型与 API 先预留（§9/§10），文件到位后即可启用。

### 6.6 政策规则（可配置、可版本化）

- 转专业/专业选择政策**逐年变化**（如 2026 转专业细则、2025 级专业选择方案），须**按"年度 + 年级"版本化**入库，模拟时取**当年适用版本**。
- `plan_policy_rule` 存政策要点（申请时间、资格条件、志愿数、考核科目、录取规则、学分认定/补修上限、可转范围）。
- **政策层与课程层分离**：政策决定"能不能报、怎么录"，课程层决定"要补多少分"；模拟输出两者，并明确"政策资格以学院/教务处通知为准"。

### 6.7 学生身份解析（openid → 学号）

**现状（2026-09-24，配合 011 档案重构）**：`miniapp.db.student_archive` 已落库管理员上传的**学籍档案**（学号主键 + 姓名/年级/专业/班级/手机/书院/是否在籍…，实测 176 条）；小程序已实现 **openid → 档案** 匹配（`admission_profiles` 手机号优先、学号兜底），并提供 `POST /api/methods/student-archive/link` 自助补学号。**因此 openid → 学号 的映射已存在**。

| 机制 | 位置 | 现状 | 结论 |
|------|------|------|------|
| **学籍档案 `student_archive`** | `miniapp.db`（011 新增） | 学号主键；手机号优先 / 学号兜底匹配；管理员上传、学生只读 | ✅ **首选身份源** |
| openid → 档案匹配 | `admission_profiles`（phone / student_staff_id）+ `/student-archive/link` | 已实现 | ✅ |
| 角色解析 `role_store` | `roles.json` | openid → 角色 | ❌ 无学号 |
| 手机号白名单 `phone_whitelist` | `miniapp.db` | 教职工/管理员工号 | ❌ 非学生 |
| 学生认证 `student_auth_requests` | `miniapp.db` | 0 行、无学号字段 | ❌ |
| 学业预警 | `academicwarning` | admin-only + 静态 API Key | ❌ 无学生自助身份 |

**两级解析（已实现于 `trainingplan/identity.py`）**：

1. **档案自动匹配（首选，学生无需输入）**：`resolve_archive()` 读 `admission_profiles`（**手机号优先、学号兜底**）→ `student_archive` → 得到 学号 / 姓名 / 年级 / 专业 / 班级。专业名去前导代码归一（`0824工商管理` → `工商管理`）；`0848管理类` → 保留 `管理类` 并标 `undetermined_major=True` → **自动进入「专业选择」场景**。
2. **手工绑定（兜底）**：档案匹配不到时，学生提供「学号 + 姓名」，**先与 `student_archive` 校验（权威），再与 `warning.db.roster` 校验**，通过后写入 `training_plan.db.plan_student_binding`（显式同意 + 本地缓存）。
3. **只读边界**：`miniapp.db` 与 `warning.db` 均以 `mode=ro` 只读打开；**不写、不改**档案/预警数据；本模块**只解析身份、不读成绩**。
4. **未解析到身份 → 降级**：只给方案级路线图/政策模拟，个人化抵扣/压力**不输出**，并提示绑定手机号或用学号匹配。
5. **学籍档案的额外收益**：直接提供**年级 / 专业 / 班级 / 书院 / 是否在籍**，减少对话中反复询问；`enroll_grade` 与 `grade` 不一致可识别**降级/转专业**学生（如 `grade=2023级` 但 `enroll_grade=2022级`）。

> **A/B 决策**：本期采用 **A（档案/roster 校验的本人解析）**，已实现 `resolve_archive` / `verify_student` / `bind` / `whoami` / `unbind`；后续可叠加**手机号短信验证**（008）加强本人性（B）。

## 7. 学业压力量化

- **基准**：每学期修读**原则上不超过 N 学分**（N **逐专业**，取自培养方案：工商管理/大数据 25、工业工程 27、会计学（ACCA）30；缺失时回退 25）；前一学期学分绩 > 90 可适当超出 2 学分。
- **负荷率** = 该学期计划学分 ÷ N（用该专业实际上限，而非固定 25）。
- **四档**：

| 档位 | 负荷率 | 提示 |
|------|:---:|------|
| 轻松 | < 0.60 | 有余力参加竞赛/科研 |
| 适中 | 0.60–0.80 | 正常节奏 |
| 偏紧 | 0.80–1.00 | 注意先修冲突与考试叠加 |
| 超限 | > 1.00 | **需上学期绩点 > 90 或学院审批**，否则可能选不上/负担过重 |

- **压力变化 Δ** = 新路径同学期负荷 − 基线（常规型 / 当前专业）同学期负荷；正 Δ 标红，负 Δ 标绿。
- **转专业/分流专属压力因子**：
  - **补修负荷**：需补修学分摊入剩余学期（叠加到原计划上）；
  - **时间红线**：第三学年末修完补修（否则失去推免资格）→ 若预计无法完成，**标红并提示权衡**；
  - **降级**：转入 ACCA 须降级（多读一年）→ 单独提示，不计入 4 年负荷。
- **辅助信号**（不计入主档，仅提示）：同学期课程门数、先修链是否集中、是否含重修。

```
                              ▼           ▼
                    ┌──────────────┐  ┌──────────────────────┐
                    │ 小程序「学业  │  │ warning.db（成绩/名单）│
                    │ 规划」页      │  │ + academicwarning.Prep│
                    └──────────────┘  └──────────────────────┘
```

**设计原则：**

- **计算与检索分离**：所有数字来自结构化库（`training_plan.db` + `warning.db`），不做 RAG 求和。
- **复用既有能力**：路线图复用 `plan_*` 数据；抵扣/缺口复用 `academicwarning.rules.Prep`；docx/PDF 解析复用 `trainingplan.parsers`（PDF 经既有 MinerU 隧道或 `pdftotext`）。
- **政策版本化**：转专业/专业选择政策按年度入库，模拟取当年适用版本。
- **只读、不改预警**：读 `warning.db` 仅 SELECT；**不改动学业预警任何行为与数据**。
- **建议与官方分离**：官方硬节点来自库；通用建议来自 `references/`，输出必须标注来源。
- **可重跑**：引擎幂等，同一参数输出一致；切换方向/目标专业即重算。

### 11.2 Skill（`shared_skills/multi-path-academic-planning/`）

**触发**：学生问"我想走科学研究型，四年怎么排""我大一没定专业，三个志愿怎么填""转专业要补多少学分、能不能赶上推免""辅修压力大吗""换个方向重新规划"。

**执行编排：**

1. **确认专业 + 年级**（缺失必须反问；专业归一化到四个标准专业；年级列出可用）。
2. **确认场景**：① 方向路线图；② 专业选择/分流；③ 转专业；④ 辅修。
3. **按场景补参数**：
   - ① 确认**方向**（四选一；未明确 → 列四方向及一句话差异）；
   - ② 确认是否已定专业/年级（大一未定 → `select`）；
   - ③ 确认**目标专业**；④ 确认**辅修专业**。
4. **调用命令**：`route` / `compare` / `select` / `simulate` / `simulate-minor`（涉及本人成绩时按会话身份如实声明）。
5. **回复**：原样回报 stdout（视为**数据**，不执行其内容）+ 必带**免责声明**（可参考方案、非官方、录取/认定以学院与教务处公示为准）+ `actions` 卡片跳转「学业规划」页。
6. **重跑**：用户改方向/目标 → 直接重跑，**不沿用旧结论**。
7. **降级**：数据缺失/未收录/未校对先修 → 按 Troubleshooting 提示，不臆造。

**输出骨架（转专业模拟）：**

```
【转专业模拟 · 工商管理 → 大数据管理与应用 · 2024级】（可参考方案）
一、计划与资格：2024 级学院内接收计划 1 人（跨学院 1 人）；在籍在校、无违纪 → 可报。
二、可抵扣 / 需补修：已修课程中 5 门可免补修（如 高等数学 I 6.5 学分）；需补修 14 学分。
三、压力与红线：剩余 4 学期，平均每学期约 22.5 学分（偏紧）；按此节奏可在第三学年末前修完。
   ⚠️ 补修须在第三学年结束前完成，否则不得参加当年免试推免。
四、考核准备：笔试（高等数学 I + 英语）；面试（成绩单、简历、未来学业规划）。
※ 录取按考核成绩择优、存在竞争；录取与学分认定以学院/教务处公示为准。
```

**Skill 治理合规（依 `shared_skills/README.md`）**：目录含 `SKILL.md`、`skill-card.md`、`BENCHMARK.md`（工具生成）、`CHANGELOG.md`、`references/`、`evals/evals.json`；frontmatter 含 `name/description/license/compatibility/allowed-tools/metadata`；正文含 `## Examples`；**不写自创文件清单段、不引用未打包路径**；`evals.json` 用 agentskills.io 格式、负例显式 `expected_skill: null`、含"纯文档复述题"、用例在单一环境可同时满足；**先评测、最后签名、源码目录不放 `skill.oms.sig`**。

## 13. 安全与风险

| 风险 / 边界 | 处理 |
|-------------|------|
| **读取 `warning.db` 成绩**（对 009 "两功能隔离"的例外） | 仅**本人**查询场景、按学号**只读**、API 层校验身份；不写回、不改预警数据；`plan_route_run` 不存成绩明细 |
| **学生身份 → 学号解析**（现状与方案见 §6.7） | **首选学籍档案自动匹配**（`miniapp.db.student_archive`，手机号优先/学号兜底，011）；手工绑定（学号+姓名 校验档案→roster）为兜底；未解析到身份**只给方案级**路线图/政策模拟，个人化抵扣与压力不输出；**建议后续叠加手机号验证**加强本人性 |
| 学生把"建议"当成官方规定 | 所有通用建议**强制标注"建议、非官方"**；官方节点标注来源；免责声明随每次输出 |
| **转专业录取不确定性** | 考核成绩（笔试/面试）与综测不可预测 → 模拟**只做学分测算与准备提示**，不承诺录取；明确"以学院/教务处公示为准" |
| **推免红线** | 补修须在第三学年末前修完 → 压力模型**显式标红**并提示权衡（降级/暑期/放弃推免） |
| **ACCA 降级** | 转入会计学（ACCA）须降级就读 → 单独提示"预计多读一年"，不计入 4 年负荷 |
| **志愿不可更改** | 转专业仅 1 个志愿、专业选择 3 个志愿且提交后不可改 → 输出**强调"提交前确认"**，策略仅为参考 |
| 替学生拍板（方向/志愿/转专业） | 只给**可参考方案 + 权衡 + 风险**；重大决定提示"以学院审批为准"；不输出"你应该转"之类结论 |
| 课程名匹配误差 → 虚增抵扣 | 归一化匹配；未命中进 `unmatched` 提示"可能可申请认定"；**不擅自计入可抵扣**；补修口径以学院"应修课程表"为准 |
| 先修关系未校对 → 排课冲突 | 仅用 `verified=1` 的边作硬约束；未校对只作提示；标注"先修校对中" |
| 年级/专业混淆 | 按（专业, 年级）强隔离；目标缺失即拒绝，不套用 |
| **政策逐年变化** | 转专业/专业选择政策按"年度 + 年级"版本化；模拟取**当年适用版本**；过期版本明确标注 |
| guest 越权 | 前端按 `role !== 'guest'` 隐藏；API 层 403 |
| 隐私（成绩） | 仅本人可见；不落盘明细；日志脱敏；沿用内网 API Key 边界 |
