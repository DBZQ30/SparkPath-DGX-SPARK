# 学业预警功能设计

> 版本: 2.3 · 日期: 2026-08-28 · 状态: 已实现 · **69 tests passed · 真实样本全链路验证通过（2026-08-27/28：148/148 成绩单 OCR 100%、129 名学生预警计算、报告三 sheet）**

> **⚠ 2026-09-24 变更：去掉「有效期 / 新鲜度」概念。** 文件不再有过期窗口（原 `FRESH_DAYS`：培养方案 / 学籍名单 / 通识课程信息表 1460 天，选课结果 / 成绩单 / 学籍异动 30 天）；`GET /api/warning/status` 不再返回 `fresh` / `fresh_days`；小程序「已上传文件」不再显示有效期标签；判重不再有"过期 → 刷新时间戳"分支（同内容重复上传直接提示已上传）。**下文凡涉及新鲜度窗口/过期拒绝计算的描述均已作废，以本行为准。**

## 1. 背景与目标

管理学院需要"学业预警"能力：基于培养方案、选课、成绩、课表、学籍异动五个数据源，批量识别每个学生的学业风险（缺必修课、学分缺口、挂科、进度落后、超选学分），向教务老师输出可行动的预警报告，并为后续学生个人消息推送 / 小程序查询预留数据结构。

> 口径说明：样本数据以 2023 级为当前届（2026-2027 学年第一学期 = 4-1，大四上学期）。学生学籍每年有变动（转专业/休学/留级/退学等），由学籍异动文件处理。

### 1.1 交付边界（本期）

| 做 | 不做（后续阶段） |
|----|------------------|
| 管理员在学业规划助手中自然语言触发批量计算 | 学生个人消息推送（学号↔用户映射未就绪，`warning_result.push_status` 预留） |
| 面向教务老师的预警报告（消息摘要 + Excel 附件） | 学生小程序 |
| 数据文件上传、解析、入库（对话发文件为主，目录扫描兜底） | 定时自动触发（本期仅手动触发） |
| 培养方案版本管理（按上传时间取最新） | |

| 学籍异动详情 | xls | 异动类别/审核状态/生效日期/学年学期/学号/姓名/年级/专业/异动后专业/异动后年级/异动后培养方案/是否同步培养方案/异动后学籍状态/预计毕业时间/是否删除选课结果 | 学生当前专业/在籍状态判定（每年变动） |

**关联规则：**

1. **学生 ↔ 培养方案**：默认按学生"当前专业"关联 4 个本科专业（0824工商管理 / 0826工业工程 / 0842会计学ACCA / 0846大数据管理与应用）对应的培养方案，每专业一份，同专业学生方案一致。**有转专业异动（审核生效）且"是否同步培养方案=是"的学生，按"异动后专业"关联培养方案**。无培养方案的专业在预警计算中跳过。
   - **专业名归一化（C1 实现）**：4 专业标准名 = 工商管理 / 工业工程 / 会计学（ACCA）/ 大数据管理与应用。培养方案正文名与成绩单文件名（含"大数据管理与用应"错字）经 `normalize_major` 统一为标准名；规则引擎按学生当前专业取该专业的应修课程集/推荐课表/学分要求（跨专业合并会导致误报，实证 8,048 条跨专业红级）。
   - **单届约束（M1）**：课表查询/选课结果按届（年级）导出（样本实证：2025-2026-2 名单全 2024级、2026-2027-1 选课全 2023级，两文件学号交集为 0）。触发时校验名单与选课学生为同一届（年级一致），混入多届则**拒绝计算**并提示。`training_plan` 预留 `entry_year` 字段（本期可空），为多届扩展留路。
2. **成绩单 ↔ 学号**：成绩单 docx 中每份成绩单顶部嵌一张学号+姓名图片，复用 `knowledge_base/ingestion/parsers.py` 的 VL 模型调用（`parse_with_vl`，公开别名 + 可选 prompt 参数）OCR 提取。图片按文档内顺序与对应成绩单表格绑定（zip 文件序 = 表格序，实证 4 份文件 148 表全部对齐）。
   - **OCR 机制（2026-08-27 实证，100% 识别率保障）**：
     - **专用学号提取 prompt**：通用描述 prompt 下本地模型 qwen3.8-27b（历史：qwen3-vl）会省略学号导致正则误判失败（实测识别率 17%）；专用 prompt（"只输出 学号：<数字> 姓名：<姓名>"）后 98.6%→100%
     - **多策略补跑**：放大 4x+对比度增强 → 原图 → 3x+二值化，3 策略 × 3 轮自动重试（轮间 5s，防服务瞬时抖动）
     - **学号正则支持字母前缀**：交流生学号（如 JL20249012）——纯数字正则漏识回归
     - **姓名↔名单交叉校正**：grade 表存 `student_name`，trigger 时学号不在名单但姓名唯一匹配（名单 129/129 无重名）→ 用名单学号覆盖，修正 OCR 漏位/错位
   - OCR 失败（多策略补跑后仍失败）：`ocr_failed_indices` 持久化到 `source_file.in_file_meta`，报告数据质量清单列出 + 回复提示人工核对重传（M3/B4）。
3. **学生基准名单**：以**与选课结果同学期**的课表查询文件为准（四专业全量，按学期导出）。触发时校验课表查询与选课结果学年学期一致（不一致拒绝计算）。选课结果/成绩单按学号挂接；缺哪个源就少算哪类规则，并在报告标注。
4. **学籍异动生效规则**：异动记录中 `审核状态 = "审核通过" 或 "2"`（"2" 为学校对专业分流完成状态的标记，视为通过）视为生效；草稿/各类"审核不通过"忽略。
   - **生效口径（M5）**：文件为多届历史流水（样本 882 条覆盖 2023/2024/2025/2026 级）。叠加时**按 `生效日期` 排序，仅应用"生效日期 ≤ 当前学期末"的最新一条**；生效日期在当前学期之后的记录本期不应用。
   - 转专业（含专业分流）→ 更新学生当前专业；`是否同步培养方案=是` → 按异动后专业关联培养方案；**`=否` → 仍按原专业方案计算，但报告附注"当前专业与计算方案不一致"**（L9）。`是否删除选课结果=是`（2026-08-28 补实现）→ 该生选课不计入（生效转专业记录，样本 26 条）；转专业学生按新专业方案计算。
   - 退学/休学/保留学籍 → 学生标记为非在籍，排除出预警推送（报告附注）；留级/复学 → 更新学生年级。**"退学警告"（学业警示）不改变在籍状态，仍参与预警计算**（2026-08-27 用户确认按当前设计确定）。
5. **跨选课 / 辅修课程**：排除出培养方案核对（学分缺口、必修核对均不计入），但在学生明细中附注"另选 X 门跨选/辅修课"（学分按培养方案课程号关联，查不到标"学分未知"）。

**课程类别映射表**（选课结果/成绩单类别 → 培养方案类别；数据驱动，可配置调整，默认值如下，经 4 专业样本核对）：

| 选课结果/成绩单类别 | 方案类别 | 方案要求学分（Table 0，工商管理示例） | 处理 |
|---------------------|----------|---------------------------------------|------|
| 公共课程 | 公共课程 | 25+(2) | 计入缺口统计 |
| 基础通识类核心课 | 模块课程·核心课程 | 6 | 计入缺口统计 |
| 基础通识类选修课 | 模块课程·选修课程 | 6 | 计入缺口统计 |
| 数学和基础科学类课程 | 数学和基础科学类课程 | 28 | 计入缺口统计 |
| 专业大类基础课程 | 专业大类基础课程 | 53 | 计入缺口统计 |
| 专业核心课程 | 专业核心课程 | 53 | 计入缺口统计 |
| 专业选修课程 | 专业选修课程 | 8 | 计入缺口统计 |
| 集中实践 | 集中实践 | 22 | 计入缺口统计 |
| 跨选课 | — | — | 排除，明细附注 |
| 辅修课程 | — | — | 排除，明细附注 |

> 方案"应修学分（截至当前学期）"由 Table 1 逐课程（开课学期 ≤ 当前学期）按类别汇总；Table 0 类别要求用于"毕业学分达成率"参考列。类别归类规则：已选课程直接取选课结果"课程类别"字段经上表映射；已修课程（成绩单）若匹配到方案课程 → 归方案课程的类型；匹配不到的 → 按成绩单标记（◇核心课/◆选修课）或课程名归并；仍无法归类的 → 报告"未匹配类别"清单。

## 3. 架构

```
新增 academicwarning/ 独立包 + 1 个新 skill（shared_skills/academic-warning/）
│
├── academicwarning/
│   ├── models.py    Pydantic 模型（培养方案/课程/学生/选课/成绩/学籍异动/预警结果）
│   ├── db.py        SQLite 存储层（data/warning.db，WAL 模式，仿 quota.db/audit.db）
│   ├── parsers.py   五类文件解析（docx/xlsx/xls）
│   │                 - 成绩单：python-docx 提取表格 + 提取内嵌图片 → VL OCR 学号
│   │                 - 培养方案：python-docx 解析 Tables 0-5（注意各专业表格列数/表头合并方式不同，需容错）
│   │                 - 选课：openpyxl；课表/学籍异动：xlrd
│   ├── rules.py     规则引擎（6 规则 → 红黄蓝分级）
│   ├── report.py    Excel 报告（openpyxl，三 sheet）+ 消息摘要生成
│   └── service.py   编排：上传入库 → 新鲜度校验 → 触发计算 → 报告生成
│
└── shared_skills/academic-warning/SKILL.md   ← 新技能（需用户同意创建，CLAUDE.md 规则 6）
```

**设计原则：**

- 独立包，不侵入 `knowledge_base`（学业预警是结构化精确计算，不是 RAG 检索）
- 复用现有能力：VL 图片理解（`knowledge_base/ingestion/parsers.py::_parse_with_vl`）、角色校验（`knowledge_base/auth/role_store.py`，5 角色中的管理员）、文件收发通道（助手现有能力）
- 存储独立 `data/warning.db`，与 quota.db / audit.db 平行
- 不引入新依赖：docx 用已装 python-docx，xlsx 用 openpyxl，xls 用 xlrd（已在探索阶段安装验证）

## 5. 计算引擎

### 5.0 成绩换算与已获学分口径

**成绩 → 及格/挂科换算表**：

| 成绩形态 | 及格（pass_flag=1） | 挂科（pass_flag=0） |
|----------|---------------------|---------------------|
| 数字 | ≥ 60 | < 60（含 0 分） |
| 字母 | A+ / A / A- / B+ / B / B- / C+ / C / C- | D+ / D / D- / F |
| 中文 | 及格 / 优秀 / 良好 / 中等 / 合格 | 不及格 / 不合格 |
| 其他 | P / Pass | 缺考（成绩为空或"缺考"） |
| 未知形态 | 按及格（pass_flag=1，报告数据质量列出，不误报挂科） | — |

**已获学分**：仅统计 pass_flag=1 课程的学分。挂科课程学分**不计入**已获学分（学分缺口、毕业达成率均以已获学分为准）。同一课程多次记录（初修 + ▲重修/△补考）以**最后一次（▲/△标记）成绩**为准；"最后一次"按**成绩单内文档顺序**判定（导出即时间序，L2）。

**必修课达成**：必修课"未达成"= 未修（成绩单无记录 **且** 选课结果本学期也无记录）**或** 已修但未通过（最后一次成绩挂科且本学期未选该课）。**本学期选课结果已有记录 → 视为"在修"，不触发规则 1/4**（避免重复预警在修的课）。规则 1 消息区分"缺修"（未修）与"未通过"（挂科）。

### 5.1 前置推导

- **当前学期编码**：由选课结果文件内"学年学期"字段（如"2026-2027学年 第一学期"）与学生年级（2023级）推导：第 X 学年 = 学年起始年 − 入学年 + 1，学期 1/2/3（3=小学期）→ 2023级 在 2026-2027 第一学期 = "4-1"。所有学生统一用同一选课文件的学期。
- **学生当前专业**：基准名单学生按学号叠加学籍异动（审核生效）：有转专业记录（是否同步培养方案=是）→ 当前专业 = 异动后专业；退学/休学/保留学籍 → 非在籍（排除出预警，报告附注）。
- **应修课程集**：`plan_course` 中 开课学期 ≤ 当前学期编码 的课程（按学期编码字符串比较，如 "2-2" > "1-2"）。**解析时校验学期编码格式（X-Y），异常值告警并列入"未识别学期"清单**（L4，如"大四（下）"等非标准格式不参与比较）。
  - **成绩待出豁免（2026-08-28 教务口径）**：开课学期 ∈（该生成绩单覆盖最大学期 `grade_max_sem`，当前学期）的课程——如 3-3 小学期专业实习刚结束、成绩 9-10 月才出——**不参与缺修判定**（成绩单无记录 ≠ 未修）。当前学期（=选课学期）课程仍按选课判定。豁免按学生粒度（留级学生成绩单覆盖学期更早）。
- **已修课程**：成绩单课程（`clean_course_name` 清洗后与方案课程名匹配，精确 → 包含）。**清洗归一化**：去 `◆▲△◇*` 与空白、全角数字/字母/括号 → 半角、罗马数字（Ⅱ）→ 拉丁字母（II）——方案"专业实习Ⅱ"与成绩单"专业实习 I"因字符差异匹配失败的实证回归。**匹配在规则侧实时清洗**（grade 入库时的旧版清洗结果与新版归一化不一致，会致匹配失效——2026-08-27 ACCA 课程误报根因）。**课程组名取子名**：方案"中文课程名称"合并列（工商/工业/会计 2 列、大数据 4 列）首列为组名（思想政治理论）、后续列第一个不同值为子名（思想道德与法治）——学生成绩单记录子名，取子名参与匹配（全员误报"缺修思想政治理论"的实证根因）。
- **已选课程**：选课结果课程（按课程号与方案课程编码匹配，**学分取 `plan_course` 的学分**——选课结果导出无学分列）。**仅统计 `选课状态=选中` 的行（M4）**；解析时回显各选课状态分布（如发现"退选/待选"等异常值列入报告数据质量）。
- **累计（已修∪已选）**：同课程只计一次；成绩单与选课结果重复时以成绩单为准（已修）；选课结果同课程号多行（初修+重修）取重修那条，学分计一次。

### 5.2 六条规则

| # | 规则 | 判定 | 级别 |
|---|------|------|------|
| 1 | 缺必修 | 应修集中必修课未达成（未修 → "缺修《课程名》"；已修未通过 → "《课程名》未通过"）；**成绩待出豁免**：开课学期在成绩单覆盖学期之后、当前学期之前的课程不参与判定 | 红 |
| 2 | 学分缺口 | 按课程类别：应修学分（方案应修课程 per 类别合计）− 已获学分（per 类别）− 本学期已选学分（per 类别，预期获得）> 0 → "XX类别还差 Y 学分" | 黄 |
| 3 | 挂科 | 成绩单成绩按 5.0 换算表判定挂科 → "《课程名》挂科（成绩 X）" | 红 |
| 4 | 重修未过 | ▲（重修）/△（补考）标记课程成绩仍挂科 → "《课程名》重修仍未通过" | 红 |

> **L1（规则 3/4 同课程去重）**：▲/△ 标记课程挂科同时命中规则 3 与规则 4，报告层以规则 4 为准，同课程不重复报规则 3。
| 5 | 超选学分 | 当前学期已选总学分 > 推荐课表对应学期学分合计 × 1.5 → "本学期选课 X 学分，超过推荐上限 Y 学分" | 黄 |
| 6 | 进度落后 | **2026-08-30 用户确认（B 方案）**：推荐课表中"已到期且成绩单已覆盖学期"的**必修**课未修（如 3-1 推荐课到 4-1 仍未修）→ "推荐课表必修课《课程名》未修（开课X-X）"；当前学期/未来推荐课成绩未出不判定（成绩待出豁免，同规则 1）；全员无成绩课程豁免（质量清单提示）；未来必修课仅提示不报预警；与规则 1 命中的同课程不重复报告 | 蓝 |

**附加输出：**

- **未来必修课提示**：开课学期 > 当前学期的必修课，未选时列为蓝级"应修"提示（不触发红/黄）。
- **跨选/辅修附注**：明细中附注跨选/辅修课门数与学分。
- **毕业学分达成率**：累计学分 ÷ 培养方案总要求学分，作为教务报告参考列，不触发预警。

**类别映射**：选课结果 `课程类别`（10 种：公共课程/专业大类基础课程/专业核心课程/专业选修课程/基础通识类核心课/基础通识类选修课/数学和基础科学类课程/集中实践/跨选课/辅修课程）与培养方案 Table 1 `课程类型` 归一化映射（**集中实践**对应方案中的实践课程：专业实习/毕业设计等）；无法归类的类别（如跨选课、辅修课程）不计入缺口统计。

## 6. 交互流程

### 6.1 数据上传

1. **入口与权限（H2/N2）**：管理员在学业规划助手对话中发文件（首选）；文件放入服务器约定目录由扫描发现（兜底）。**对话上传路径复用 `role_store` 校验 admin，非管理员上传直接拒绝**（与 §6.2 触发权限对称；系统 `file` 工具对 student/teacher 开放，须在 service 层拦截）。**目录扫描兜底路径无用户上下文，无法做角色校验（N2）——该路径的信任边界落在文件系统权限（约定目录权限由运维控制，仅管理员可写），文档明确此边界，不额外加码。**
2. **类型识别**（三级优先级，实现与描述一致）：
   - 文件内信息：选课结果首行首列"学年学期"、课表查询表头（学号/姓名/选课门数/学分数）、学籍异动表头（异动类别/审核状态）、培养方案正文段落含"培养方案"字样、成绩单表格表头含"课程"+"成绩"
   - 文件名关键词：选课结果 / 培养方案 / 成绩单 / 课表 / 学籍异动
   - 对话说明（"这是大数据的选课结果"）
3. **解析入库**：培养方案按专业+上传时间进入版本管理（新版激活、旧版标记历史）；成绩单先 OCR 学号图片再入库；学籍异动仅审核状态="审核通过"/"2" 的记录入库。
4. **回复确认**：识别类型、覆盖学生范围、上传时间、课表查询与选课结果的学期一致性；解析失败时说明原因并给出重传指引。
5. **重复与覆盖（H1/M2）**：
   - **多文件类型（H1）**：`grade`（每专业一份）与 `plan`（每专业一份）为**按专业多文件类型**——同类型内按专业各取最新文件，**计算时合并全部专业的最新文件**；`selection`/`roster`/`status_change` 为全局单文件类型——计算只用最新上传的一份。触发时核对 4 专业成绩单齐全性，缺某专业文件 → 该专业学生结果标注"成绩数据缺失"（与 M3 联动），不静默少算。
   - 文件哈希已存在且内容未变 → 提示"该文件已上传过（上传时间 X）"，不重复入库；**但该类型当前活跃文件已过期（M2）时，允许重传并刷新 `upload_time`**，回复注明"原文件已过期，已刷新时间戳"
   - 同类型新文件上传（内容不同）→ 旧文件数据保留在库（按 `source_file_id` 区分），计算只取最新；回复中提示"旧文件 X 已被新文件覆盖"
   - 培养方案例外：同专业新方案按版本管理（见第 2 节），不覆盖

### 6.2 触发计算

1. **入口**：管理员在学业规划助手中自然语言触发，如"跑一下学业预警"（可带范围：全部 / "只算工商管理" / "查一下学号 9000000040"）。
2. **权限**：`role_store.py` 角色校验，仅管理员（admin）可触发；非管理员回复无权限提示。
3. **数据新鲜度**：五类文件（培养方案/选课结果/成绩单/课表查询/学籍异动）均需存在且上传时间 ≤ 新鲜度窗口（**按类型差异化（M2）：培养方案 4 年（1460 天）保持整版，其余 30 天，可配置**）；缺失或过期 → 回复告知需先上传哪类文件。另校验课表查询与选课结果学年学期一致、名单与选课学生为同一届（M1），**不一致时拒绝计算**并提示先上传正确文件。
4. **范围回显（L8）**：意图解析出的范围参数在计算前显式回显确认，如"计算范围：全部 129 人 / 工商管理 35 人 / 学号 9000000040"，确认后执行。
5. **计算**：按范围过滤学生，叠加学籍异动确定当前专业/在籍状态，执行 6 规则，结果入库。**计算只选 `parsed_status=done` 的最新文件**（L7）。
6. **报告**：消息摘要 + Excel 附件回复管理员。
7. **并发（L7，2026-08-28 补实现）**：模块级 `threading.Lock`（`_OP_LOCK`）包裹 upload_file/trigger_warning 写库关键路径，防止解析与计算并发读到半入库数据；计算同步执行（样本规模小，单次秒级），已有任务进行中后续调用等待锁释放。

  - 数据质量：课表"选课门数/学分数" vs 计算值不一致的学生清单（已实现）、成绩单未匹配方案课程清单（已实现）、名单外学生清单（已实现）、OCR 学号无法识别份数（已实现，`ocr_failed_indices`）

  - 学号/姓名/专业/班级/在籍状态/预警级别/数据缺失标记
  - 缺修必修课列表（含课程编码、开课学期）

  - 超选说明（已选学分/推荐上限）
  - 进度落后列表（本学期推荐课程未选）
  - 未来必修课提示列表
  - 跨选/辅修附注（门数、学分）
- `学生个人报告`：学号/姓名/个人报告文本（**为后续消息推送/小程序预留的字段模板**，每条消息含规则、级别、建议）

**名单外学生（L10）**：成绩单/选课中存在但不在课表基准名单的学生（样本 148 vs 129 即有差）——成绩仍入库（供将来名单刷新后用），**不出现在预警明细**，在报告"数据质量"清单列出。

报告文件命名 `学业预警-YYYYMMDD-HHMMSS.xlsx`，存 `data/warning_reports/`（绝对路径锚定仓库根）；**保留策略（L6，2026-08-28 补实现）：保留最近 12 期，生成报告后自动清理更早的报告（`_cleanup_reports`）**。

## 10. 风险与边界

| 风险/边界 | 处理 |
|-----------|------|
| 成绩单图片 OCR 失败（M3/B4） | 多策略补跑（3策略×3轮）后仍失败的极少数：`ocr_failed_indices` 持久化到 `source_file.in_file_meta`，报告"数据质量"清单列出份数，回复提示"请人工核对后重传/补录"；失败份数无学号无法关联学生（B4 决议，`data_incomplete` 为规则引擎预留字段） |
| 课程名匹配歧义（重名课程、简写） | 精确匹配优先；无法匹配计入已修学分但不参与必修核对，报告中列出"未匹配课程"清单 |
| 数据过期误算 | 触发前强制新鲜度校验，过期即拒绝计算并提示上传 |
| 专业无培养方案 | 该专业学生跳过方案类规则（1/2/5/6），成绩类规则（3/4）仍计算，报告中注明 |
| 课表查询与选课结果学期不一致 | 触发时校验并提示，拒绝计算或要求先上传同学期课表 |
| 转专业学生成绩跨两个专业方案 | 成绩单课程名同时匹配新旧专业方案；预警按当前专业（异动后）方案计算，无法匹配的已修课程计入已修学分但不参与必修核对；`同步培养方案=否` 的学生附注"当前专业与计算方案不一致"（L9） |
| 大文件性能 | 样本约 148 名学生（4 份成绩单文件共 148 个表 + 148 张学号图 OCR），OCR 全量实测 ~3.5 分钟（逐张 + 间隔 + 补跑），计算秒级——同步执行可接受；如数据量增长改为异步 + 完成通知 |
